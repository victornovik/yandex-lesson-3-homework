**Общая идея.** Ставки уже попадают из АБС в Kafka и в микросервис ставок. Новое решение добавляет двух потребителей:

- система кол-центра банка запрашивает ставки у сервиса ставок по REST и кеширует их;
- новый сервис выгрузки ставок создает CSV файл со ставками и аплоадит его на SFTP, откуда файл забирает система партнёра.

**Логика принятых решений**

- **Единый источник ставок.** Ставки ведутся только в АБС. Дополнительные ручные копии (Excel, письма) не появляются (F3).
- **Кол-центр банка по REST, не через Kafka.** Это платформа подрядчика, и делать её интеграцию с Kafka на данный момент нельзя. Интеграция по REST вписывается в её расширяемую модель (S7, +R6).
- **Файлы для партнёра.** Партнёр не может использовать API, поэтому ему подходит хранение CSV файлов на SFTP сервере. Банк выкладывает файл на SFTP сервер, а партнёр забирает его.
- **Отдельный микросервис выгрузки ставок.** Выгрузка реализуется не в микросервисе ставок, чтобы сбои файлового обмена не влияли на запросы ставок (R6). Так же в будущем возможны другие интеграции и выгрузки ставок по другим протоколам, нежели чем SFTP.
- **Защита АБС от перегрузки.** Ни кол-центр, ни выгрузка ставок не обращаются к АБС. Кол-центр читает кэш сервиса ставок (P5).
- **Устойчивость.** Атомарная замена файла со ставками. Регулряная ежесуточная по расписанию выгрузка. Алерты на сбои выгрузки (R6, R7, UC6).

| **№** | **Альтернатива**                                                                                  | **Почему отклонена**                                                                                                                                                                                |

|  A1   | Кол-центр банка читает ставки напрямую из БД или API АБС                                          | БД АБС перегружена и масштабируется только вертикально. Рост звонков после старта кампании создаст дополнительную нагрузку на АБС.                                                                  |
|  A2   | Система кол-центра подписывается на Kafka                                                         | Платформа подрядчика, интеграция с Кафкой невозможна в данный момент.                                                                                                                               |
|  A3   | Операторы вводят ставки в систему кол-центра вручную или по Excel файлам (как сейчас в бэк-офисе) | Дублируется ввод, повышается вероятность ошибок при ручном вводе, повышается риск отдачи клиентам устаревших ставок                                                                                 |
|  A4   | Выгрузка файла напрямую из АБС по расписанию                                                      | Добавляет нагрузку на АБС. Нарушает разделение ответственности: АБС не должна знать о потребителях                                                                                                  |
|  A5   | Выгрузка в сервисе ставок                                                                         | Сбои выгрузки и файлового обмена могут повлиять на онлайн-запросы ставок. Ухудшится масштабирование и независимые релизы. Вероятно появление иных интеграций по другим протоколам, нежели чем SFTP. |

**Недостатки, ограничения, риски**

- **Задержка у партнёра.** Файл обновляется с задержкой (до 15 минут) и по расписанию у партнёра. Оператор партнерского кол-центра может назвать ставку, которая только что изменилась.
- **Зависимость от партнёра.** Реализация загрузки файла и показа ставок остаётся на стороне партнёра. Риски по срокам.
- **Подрядчик кол-центра.** Блок «Ставки по депозитам» зависит от возможностей платформы. Если расширение невозможно, потребуется обходное решение.
- **Новый сервис и протокол в системе.** SFTP-сервер и сервис выгрузки добавляют эксплуатационную нагрузку: мониторинг, резервирование, бэкапирование.
- **Безопасность.** Доступ по whitelist IP-адресов. Нужно настроить DMZ и аудит обращений. Ставки не являются ПДН, но их подмена может повлечь спорные случаи.
